# Plan: lessons from a shipped game (0.1.3 → 0.2.0)

Run with AI Plan Loop: `python <ai-plan-loop>\plan_loop.py <repo>\docs\PLAN.md` (the log is `docs/PLAN.progress.md`, next to this file). Read `AGENTS.md` and `docs/ARCHITECTURE.md` first. The AGS 3.6.2.21 source for API lookups is `AgsSourceDir` in `Local.props`; source paths below are relative to it. The tool reference is `README.md#tools` and `skills/ags-mcp/references/tools.md`.

## Why

A complete game was built through this server. Its project accumulated ~40 helper scripts, each filling a gap in the server: release builds tested by real Win32 input because the `game_*` tools need the runtime plugin and Debug mode; a raw JSON-RPC client for bulk passes; font files patched by hand; text widths re-measured from WFN files; `Game.agf` patched for GUI controls and module order; the editor's stale in-memory copy of a script compiled over a disk edit; LF/CRLF rewrites from `set_dialog_script`. This plan moves each of those into the server or the skill.

## Rules for every milestone

- **Project-agnostic.** Nothing added may name a particular game, its rooms, characters, scripts or sprite numbers, nor any machine path. Machine paths come only from the git-ignored `Local.props` or from tool arguments; examples use neutral names (`roomN`, `cPlayer`, `<game>`). This restates `AGENTS.md`: "Don't add references to specific games."
- `AGENTS.md` constraints: C# 7.3, net46, one DLL (`Private=false`), schemas with one typed form (no `anyOf`/`oneOf`/`$ref`), editor internals only in `src/AgsMcp.Editor/EditorInternals.cs`, bad input throws `ToolException`, UI-thread tools through `UiDispatcher` (`RunOnUiThread=false` only for tools that never touch the editor model).
- Dev loop: `.\build.ps1 -Test -Deploy -StopEditor -Run` (add `-Engine` for C++ milestones; needs VS 2022 with the C++ CMake tools). With no game open every tool call is refused: `-Run` opens the smoke game when `-Game` is absent (`SmokeGame` from `Local.props`, else `%LOCALAPPDATA%\AGS-MCP\SmokeGame\Game.agf`, created from a template when missing), and `-StopEditor` saves whatever game is open through `save_project` before it kills the editor (decision 16). Neither needs the owner: never end a turn `BLOCKED` over `SmokeGame` or an open editor.
- **Gate** = unit tests green (`.\build.ps1 -Test`) **and** the milestone's named `tests/smoke/smoke.ps1` checks pass against the live editor, with the observed output quoted in the progress log. Smoke checks are `Check "label" { ... }` blocks using `Invoke-Mcp`/`Get-Json`/`Has-Image`; the smoke game is throwaway, so temporary script hooks are allowed there.
- **Docs in the same commit:** `README.md#tools` row(s), `skills/ags-mcp/references/tools.md` row(s), `docs/ARCHITECTURE.md` (the behaviour section, Known gaps, and any newly verified AGS fact in "AGS reference").
- The skill stays client-neutral (tool names without a client prefix) and never names a particular game.

## Decisions

1. Plan here, log in `docs/PLAN.progress.md` (owner).
2. Release testing = cheap toggle (`runtime_disable_plugin`, `build_game mode`) **and** an in-server Win32 desktop driver (`desktop_*`) that drives any AGS exe by real input without the plugin (owner).
3. Text measurement = server-side WFN parser (`measure_text`; TTF refused) **and** engine `text_extent` via `IAGSEngine::GetTextExtent` (owner).
4. Version 0.2.0 is the last milestone (owner).
5. No array forms on `import_sprite`/`replace_sprite`: `batch` makes every tool bulk-capable while each schema keeps one typed form.
6. No separate `replace_font`: `import_font id path` replaces that slot's file; `create_entity font` makes a new slot as a copy of an existing font, as the editor does.
7. `list_strings` walks the model itself, mirroring `TextProcessingHelper`, instead of implementing `IGameTextProcessor`: the processor callback carries no source, `Script` text arrives as whole files, and the room walk lives in a private `RoomsComponent` handler. Rooms are opt-in (`rooms=true`) through `RoomSession`.
8. `game_run_interaction` is a **queued click** at a point computed from editor data and confirmed with `hover_name`; it never calls `ProcessClick` inside PRERENDER, and refuses when no sampled point reports the target.
9. `build_game`/`run_game` save first and honour `NeedsRebuildForDebugMode()`, as the editor's own Build command does. This is a behaviour change; record it in ARCHITECTURE.
10. No `scripts/mcp_client.py` in the skill: `batch` and the smoke test's `Invoke-Mcp` cover raw access.
11. No post-install connection check in `install.ps1` (it refuses while the editor runs); its Next steps print a `GET http://127.0.0.1:7471/` check instead.
12. Text into GUI text boxes is a separate `game_type text` (WM_CHAR), not an overload of `game_key`.
13. (2026-10-19) A gate's "Select-String over the repo" means tracked files: git-ignored local files (`.vscode`, `skills/ags-mcp-workspace`, `.ai-loop` logs) are the owner's and are left as they are.
14. (2026-10-19) Superseded by 16.
15. (2026-10-19) `tools/LocalProps.ps1` needed no change: `Get-LocalProp` reads any element, so `SmokeGame` is read with `Get-LocalProp SmokeGame` in `build.ps1`.
16. (2026-10-19, owner) Live gates never block on the owner. `SmokeGame` is optional: `tools/SmokeGame.ps1` defaults it to `%LOCALAPPDATA%\AGS-MCP\SmokeGame\Game.agf` and creates it by extracting the Sierra-style `.agt`. `build.ps1 -StopEditor` calls `save_project` on the running server, then kills the editor whatever project is open, even when the save fails. An unattended session may run `-StopEditor` with any project open and may leave the smoke game open afterwards.
17. (2026-10-19) `reload_script` reloads a room script in place (`Script.LoadFromDisk()`) instead of `UnloadScript()` + `LoadScript()`: the loaded `Room` and its `UnloadedRoom` share one `Script` object, and a fresh one would leave the loaded room compiling the old text.
18. (2026-10-19) `staleOnDisk` ignores newline style and trailing newlines (only a save round-trip changes those); on `compile` it is a list of stale files among the compiled bodies and all module headers, since a stale header changes the compile too.
19. (2026-10-19) `batch` embeds a call's JSON text parsed (other text stays a string), so a reply is not JSON inside JSON strings; the batch result itself is never `isError` (per-call `ok` carries failures), and `stopped` is true only when later calls were skipped. It is annotated destructive, since its calls may be.
20. (2026-10-19) `outPath` returns `{path, width, height, note}`: `note` keeps the text the tool returns beside the image (`render_room`'s mask legend). Parent folders are created; only rooted drive or UNC paths are accepted (`ImageOutput.IsAbsolutePath`).
21. (2026-10-19) `create_sprite_folder` keeps names unique across the whole tree by appending a number and returning the actual name, as `create_script_module` does, rather than refusing: every sprite tool finds folders by name, first match. `move_script_module` up/down at an end is a no-op (`moved=false`), not an error.
22. (2026-10-19) A `gui:control` side matches a control's name before its ID. GUI and control stubs go to `GUI.ScriptModule` (GlobalScript by default), as the GUI editor does, and default to `<scriptName>_<property>`; `event` accepts the property name or it without `On` (`Click`). `get_properties` on a GUI or control reports `events` as `{property: function}`. `create_gui_control` reports properties it could not apply in `ignored`, like `create_entity`.
23. (2026-10-19) Build parity: `NeedsRebuildForDebugMode`, `SaveGameFiles` and `SaveUserDataFile` are public on `AGSEditor` (no reflection); `CompileGameFull` also saves the user data file after the build, as the editor does. A failed save throws. `build_game` stops a game started by `run_game`, kills leftover processes of the built exe (`GetProcessesByName`, then `MainModule.FileName`) and waits for its files first. The build retry looks at errors only ("Failed to delete a temporary file" is also a warning on good builds). `mode=debug` sets Debug mode even without the plugin installed; `runtime_disable_plugin` leaves a copied `agsmcp.dll` in place (only `mode=release` deletes it). A mode change is saved with the project even when the build then fails. Both tools return `mode`, `debugMode` and `enginePlugin`.
24. (2026-10-19) Fonts: `import_font` lives in its own `Tools/FontTools.cs` (with the font kind's `Create`), not `AssetTools.cs`, which is sprites and views. A TTF import without `height`/`pointSize` keeps the font's current point size, else 10 (the editor's import dialog default); a WFN import refuses both (a bitmap font scales by `SizeMultiplier`). A rejected file restores the slot's old files instead of leaving it half-imported. No font delete (it renames every later slot's file, and scripts address fonts by number). The font kind's `AfterChange` pushes every font to its native slot, as the font pane's `PropertyChanged` does.
25. (2026-10-19) `list_strings` always includes room-script literals (read from memory or disk, no room load); only messages, descriptions and properties need `rooms=true`. Dialog scripts yield speech lines (`name: text`, with `speaker`) as well as script-line literals, as `GameSpeechProcessor` does, since speech is the text most worth measuring. Literals are returned as written (escapes not decoded), as the translation source has them. It adds a `contains` filter. `measure_text` returns `lineCount`, `fontHeight` (outlined) and `notes` besides the planned fields, and a non-Unicode game's text is mapped to its encoding's bytes before measuring.
26. (2026-10-19) Engine shutdown answers the request being handled (it can be the one that quit the game: `QueueGameScriptFunction` runs `QuitGame` at once) with `{ok:true, gameExiting:true}`, then gives the worker up to 2 s to send it and leave through its 500 ms receive timeout before force-closing the client socket. The plan's immediate `shutdown(SD_BOTH)` of the client would lose that answer and make `game_call_function` report a failure for a quit that worked. The editor always deletes the screenshot BMP after reading it, `outPath` or not. `game_key` results gain `code` and `via`.

27. (2026-10-19) `game_run_interaction` targets are `hotspot:|object:|character:` (alias `char:`) with an ID or script name, or a bare script name (hotspots, then objects, then characters); a bare number is refused as ambiguous. It also refuses a target with no description (nothing for `hover_name` to confirm) and a click while `interfaceEnabled` is 0. The hover check uses a `room=1` flag on the engine's `hover_name` (converted by `RoomToViewport`, like `process_click`) rather than the editor guessing the camera. Characters match their live `name` from `game_state`, hotspots and objects their editor `Description`; character scaling is ignored.
28. (2026-10-19) `game_text_extent` sends a non-Unicode game's text as codepage `bytes` (the bridge is UTF-8 JSON), as `measure_text` maps it; it measures one line (no `[` breaks), the engine call's contract.
29. (2026-10-19) `get_game_log` (`SliceLog`) treats the log's final newline as the end of the last line: counting the empty tail made `nextLine` one past the next line written, so a poll missed a lone new line. Milestone 11's `logLine` wait builds on this.
30. (2026-10-19) `game_wait_until logLine` reads the log file, not the engine (it works while the game blocks); `sinceLine` defaults to the log's end when the wait starts, so earlier matches never satisfy it, and callers pass `get_game_log`'s `nextLine` taken before the action. It stops early when the game has exited.
31. (2026-10-19) A burst is capped at `frames × everyN ≤ 2000` game frames (the tool's 240 s timeout covers the engine's 100 ms-per-frame budget). It overwrites `frame-NNN.png` in the directory and does not delete older frames; `frames.json` lists this burst's files. The engine keeps draining its queue during a burst, but the editor's one connection (and the worker, one request at a time) waits for the burst's answer, so a click cannot be sent mid-burst: take a burst after the action. The "screenshot staleness" playtesting note goes into `playtesting.md` in milestone 14; this milestone put it in the `game_screenshot` tool text and `tools.md`.
32. (2026-10-19) `desktop_screenshot` captures with `PrintWindow(PW_CLIENTONLY | PW_RENDERFULLCONTENT)` first (reads a covered window, no focus theft) and falls back to foreground + `CopyFromScreen` only when that reads all black; the result names the `method`. DPI awareness is per thread (`SetThreadDpiAwarenessContext`), not `SetProcessDPIAware`, which would change the whole editor process. `desktop_run`'s `exe` is optional (the open game's build), it adds `--no-message-box` like `run_game`, and it removes `AGSMCP_PORT` from the child environment so a debug build's plugin stays inert.

33. (2026-10-19) Desktop input: the Alt-tap focus unlock runs only when the game window is not already in front, and a tool that cannot bring it forward (or, for a click, finds another window over the point) refuses and sends nothing, since `SendInput` lands in whatever window is in front. Keys and clicks both go through `SendInput` (not `mouse_event`). `desktop_key` takes `Ctrl+`/`Shift+`/`Alt+` chords and `holdMs` (keyboard movement); `desktop_type` refuses control characters. `game_wait_until logLine` gained `get_game_log`'s `source` (default: the game launched last), so a desktop game's log markers can be awaited; before, it always read the `run_game` log.

34. (2026-10-19) Skill update: every tool already had its `tools.md` row (each milestone added its own), so 14 added none. Budget and `batch` went into a new playtesting section, not the caveats list, since neither looks like a bug. The release-build check runs in the same play-test subagent as the `game_*` loop, and the skill tells the agent to warn the user about focus first. `scripting.md` already had define-before-use; the stale-copy line there gives the symptom and points to `reload_script`, while SKILL.md keeps the rule. A claim that colour numbers below 32 are palette slots was left out: not found in the 3.6 source.

## Verified facts (AGS 3.6.2.21 source and this repo)

- **Plugins** (`Editor/AGS.Editor/Components/PluginsComponent.cs`): private `List<NativePlugin> _plugins`; `BeforeSaveGame` rebuilds `Game.Plugins` from the enabled entries; `RefreshDataFromGame` re-enables from `Game.Plugins`; private `RepopulateTreeView()` redraws the tree icons. `NativePlugin.Enabled=false` calls the DLL's `AGS_EditorShutdown`. `BuildTargetWindows.CopyPlugins` copies enabled DLLs into `Compiled\Windows` and never deletes, so a stale `agsmcp.dll` must be removed by us. `EditorInternals.EnableEnginePlugin` (reflection over `_plugins`) is the template for the disable path.
- **Build** (`BuildCommandsComponent.CompileGame`): `forceRebuild = NeedsRebuildForDebugMode() || forceRebuild; if (SaveGameFiles()) CompileGame(forceRebuild, false)`. `NeedsRebuildForDebugMode` compares `Settings.DebugMode` with `WorkspaceState.LastBuildConfiguration` and updates it. The server's `EditorInternals.CompileGameFull` currently skips both calls. "Failed to delete an old file" comes from `TryDeleteFile` in the build targets; "EndUpdateResource … 0000006E" from `AGS.Native/agsicons.cpp` patching the icon of a still-locked exe. Data file: `Compiled\Data\<BaseGameFileName>.ags`.
- **Scripts**: `Script.LoadFromDisk()` re-reads `FileName` with the game's `TextEncoding` and clears `Modified` (never called by the server today). `ScriptsAndHeaders.MoveScriptAndHeaderUp/Down(ScriptAndHeader)` move by one in the flat list only. `Dialog.ToXml` writes `Script` with `WriteCData` verbatim, and CRLF inside CDATA reads back as LF. `ScriptTools.Save` forces CRLF; `set_event` and `set_dialog_script` (normalised itself) now do too. The dialog pane (`Panes/DialogEditor.cs`) builds scripts with `Environment.NewLine` and finds an option's section by `Contains(Environment.NewLine + "@" + id)`. `UnloadedRoom.LoadScript()` only loads when `_script` is null; `Script.TextEncoding` is a public static.
- **GUI controls**: `GUI.Controls` is `List<GUIControl>` `[Browsable(false)]`; `GUI.DeleteControl` removes and decrements higher IDs. `GUIEditor.CreateNewControl` recipe: `new GUIButton/GUILabel/GUITextBox/GUIListBox/GUISlider/GUIInventory(x,y,w,h)`, `Name = GetFirstAvailableScriptName(c.ControlType)`, `ZOrder = ID = gui.Controls.Count`, `Parent = gui`, `gui.Controls.Add(c)`, `game.NotifyClientsGUIControlAddedOrRemoved(gui, c)` (public). Event properties carry `[ScriptFunctionParameters]`: `GUIButton.OnClick` and `NormalGUI.OnClick` (`GUIControl *control, MouseButton button` / `GUI *theGui, MouseButton button`), `GUIListBox.OnSelectionChanged`, `GUITextBox.OnActivate`, `GUISlider.OnChange` (`GUIControl *control`).
- **Fonts** (`FontsComponent.cs`, `NativeProxy.cs`, `AGS.Types/Font.cs`): new font = `new Font{ID=Fonts.Count, Name="Font N", OutlineStyle=None, PointSize and SourceFilename from the copied font, ProjectFilename="agsfnt{ID}"+ext, TTFMetricsFixup=Settings.TTFMetricsFixup}`, `Fonts.Add`, copy `agsfnt{from}.wfn|ttf` → `agsfnt{to}` with `File.Copy` (the editor's `Utilities.CopyFont` lives in an **internal** class), `NativeProxy.OnFontAdded(game,id)`, `FontTypeConverter.SetFontList(game.Fonts)` (public). TTF import: copy to `agsfnt{id}.ttf`, delete the `.wfn`, `NativeProxy.ReloadFont(id)`, `PointSize = FindTTFSizeForHeight(file, px)` when a pixel height is given (else 10), `SizeMultiplier=1`, `ProjectFilename=TTFFileName`. WFN import: copy to `.wfn`, delete the `.ttf`, `ReloadFont`, `PointSize=0`. Both end with `OnFontUpdated(game,id,true)`. Font files are relative to the game folder (the editor's working directory). `NativeProxy` is internal: reach it by reflection as `EditorInternals` already does for sprites (`EditorInternals.OnFontAdded/OnFontUpdated/ReloadFont/FindTTFSizeForHeight` now exist). `FindTTFSizeForHeight` needs a game-relative name (`agsfnt<N>.ttf`): the native loader opens it through the asset manager, and an absolute path fails as "Not a TTF font" (verified). `OnFontUpdated` writes `Font.Height` and `FamilyName`.
- **WFN** (`Common/font/wfnfont.cpp`, `wfnfontrenderer.cpp`, `fonts.cpp`): signature `"WGT Font File  "` (15 bytes), `u16 table_addr` at offset 15, `char_count=(size-table_addr)/2`, `u16` glyph offsets (0 = no glyph), glyph record `{u16 w, u16 h, ((w+7)/8)*h bytes}`. Line width = Σ glyph widths × `SizeMultiplier`; height = max glyph height × multiplier; an automatic outline adds `2*AutoOutlineThickness`; an outline *font* takes `max(self, outline)`. `split_lines`: `maxWidth -= 1`, `[` is a line break (`\[` literal), break at the last space, else inside the word; line step = `LineSpacing` (0 → font height + 2×thickness). Glyph offsets are absolute file offsets; a WFN font's height is the text height of `"ZHwypgfjqhkilIK"`. `WfnFont`/`WfnTextMetrics` implement all of it and matched the engine's `GetTextWidth`/`GetTextHeight` on font 0 (verified).
- **Engine plugin API** (`Engine/plugin/agsplugin.h` v30): `GetTextExtent(font, text, &w, &h)` (outlined; "Hi" in the smoke game's font 0 = 12×12 = `measure_text`, verified); `GetFontType` is inverted (bitmap → `FNT_TTF`), usable only for `FNT_INVALID`; `GetLocationName` takes screen coordinates; `QueueGameScriptFunction(name, globalScript=0, …)` runs the function in the **room** script (verified), at once when no script is running; `SaveScreenShot` picks the format from the extension. No `RunInteraction`/`ProcessClick` and no `AGSE_FINALSHUTDOWN` in this version. The script alive timer is `ccSetScriptAliveTimer(1000/60, 1000, 150000)` (`Engine/game/game_init.cpp`): a script that loops 150000 times without yielding is aborted. `RestoredSaveInfo::GUIControlCount` exists (`savegame.cpp`); "reads 0" was reported by a project, not verified.
- **Keys**: `Game_SimulateKeyPress` → `ags_key_to_sdl_scan` maps Home/arrows/PgUp/PgDn/End/Ins/Del to the **NumPad** scancode first, and with NumLock on they become digits; codes 1–26 are Ctrl+letters, 301+ are Alt+letters. The plugin's `post_window_key` now sets the extended-key bit (`lParam` bit 24) for the navigation keys, and `game_key Up`/`F7` reach `on_key_press` as 372/365 (verified). `WM_CHAR` reaches `on_text_input(ch)` (verified); `on_key_press` gets key events only when `ki.UChar == 0` in the new key-handling mode (`Engine/main/game_run.cpp`).
- **Shutdown**: `AGS_EngineShutdown` closes the listening socket and `join`s the worker, which may be blocked in `recv()` on the persistent client connection (no `SO_RCVTIMEO`, no `shutdown()` of the client socket); a request arriving during shutdown waits the full 10 s because PRERENDER no longer drains the queue. This is the probable cause of the 15–90 s Quit a project reported. Fixed in milestone 9; the remaining cause was the request that called `QuitGame` itself, which shutdown never answered (verified: exit now 175–226 ms after `game_call_function MCP_Quit`).
- **Text extraction** (`Editor/AGS.Editor/TextProcessing/`): `TextProcessingHelper.ProcessAllGameText(IGameTextProcessor, Game, CompileMessages)` (public) covers the game name, dialog options and scripts, module scripts, custom-property defaults, GUI labels and buttons, `Character.RealName`, `InventoryItem.Description`, `GlobalMessages`, then fires `ProcessAllGameTexts`; `RoomsComponent` answers it by loading **every** room (unloading the current one) for room scripts, messages, hotspot and object descriptions. `GameTextType {Unknown, Script, DialogScript, Message, DialogOption, ItemDescription}`.
- **Desktop window** (milestone 12): `desktop_run` of the 320×200 smoke game with `--windowed` opened a 1920×1200 client area (scale 6, offset 0) at screen (320,120) on this machine, physical pixels under the thread's per-monitor DPI awareness; `PrintWindow` captured it correctly. `desktop_click` lands on `DesktopGeometry.GameToScreen`'s pixel centre (game 75,147 → screen 773,992 with the client at 320,107, scale 6). A minimised window can still be the foreground window. Real Escape, Up, text and right/left clicks reach the release build (milestone 13 smoke).
- **Script engine** (`Engine/script/cc_instance.cpp`, `Engine/ac/dialog.cpp`, `Engine/ac/game.cpp`): the hang guard counts backward jumps and fails with "Script appears to be hung (a while loop ran %d times)"; `noloopcheck` disables it per function. Dialog options are drawn in `FONT_NORMAL`. `Game.GetColorFromRGB` is plain RGB565 for any non-8-bit depth.
- **Smoke game**: the Sierra template's F7 opens its restore dialog, a modal popup GUI that pauses the game and covers the room (hover reads ""); Escape opens the control panel, and with the panel open it closes and reopens it (the template's second `if` chain is not `else`-joined); its Resume button closes it. The smoke test closes them with a GlobalScript hook (`MCP_HidePopups`: hide every `eGUIPopupModal` GUI). The engine log ends every message with `\n` and flushes (`Engine/debug/logfile.cpp`).
- **Server**: the listening and accepted sockets are non-inheritable (milestone 13): a child game inherited the listener and kept port 7471 after the editor was killed.
